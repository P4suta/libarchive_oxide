# Changelog

Notable changes are generated by [release-plz](https://release-plz.dev).

## [Unreleased]

### Added

- Added host-specific validated extraction destinations: whole-plan preflight
  preserves Unix byte/case identity while Windows rejects reserved devices,
  ADS and trailing-dot/space spellings and detects case-insensitive or NFC/NFD
  aliases before adapter startup or payload writes.
- Added a bounded, read-only `no_std + alloc` WARC 1.0/1.1 decoder with exact
  CRLF signature/framing, mandatory finite `Content-Length`, validated
  case-insensitive named fields preserved as extensions, collision-free record
  paths, public Pipeline/reader wiring, standards-derived interoperability and
  negative/resource tests, and reused fuzz-target/corpus coverage.
- Added bounded read-only CAB LZX across `15..=21`-bit windows using an
  attributed, audited `no_std + alloc` regular-LZX fork. Decoder history
  persists across word-aligned CFDATA frames; makecab/libmspack fixtures,
  checksums, malformed streams, and codec-memory/in-flight/decoded-total
  limits are gated.
- Added the `no_std + alloc` `libarchive_oxide-codecs` crate and moved the
  bounded gzip/Deflate, Zstandard, LZ4, BCJ, and Delta state machines behind
  additive algorithm features while preserving the flagship adapters.
- Added bounded, read-only Unix `compress(1)` / `.Z` LZW across codec,
  provider, sync/async archive-reader, capability-ledger, and fuzz-replay paths,
  with independent `compress` and bsdtar fixtures; creation remains absent.
- Added a read-only `empty` format whose decoder accepts only explicit EOF
  with zero decoded bytes; unknown non-empty input remains unsupported.
- Added a read-only raw format that streams one unknown-size `data` entry only
  when selected explicitly through sync, async, Tokio, pipeline, or engine
  APIs; raw is never an automatic fallback and enforces decoded byte limits.
- Expanded the shared libFuzzer/stable-replay suite from 19 to 27 targets with
  CAB and XAR parser coverage plus bounded RPM, Alpine, ZIP-ecosystem, APK,
  IPA, and MSIX package-verifier invariants, safe-extraction policy planning,
  bounded Unix `compress(1)` LZW decoding, and committed hostile seeds.
- Added validated encoded paths, timestamps, sparse extents, algorithm-tagged
  checksums, fallible metadata assembly, and writer-side pre-I/O validation;
  unified everyday archive/I/O failures under the root `Error`.
- Added stable byte-sorted filesystem creation, duplicate archive-path
  rejection, and an `oxarchive create --reproducible` metadata profile.
- Added streaming XAR `application/x-bzip2` reads with exact decoded-length,
  checksum/corruption, trailing-data, and codec-memory enforcement.
- Added portable streaming ZIP Zstandard writes using bounded raw-block frames,
  with runtime portable/native backend selection, independent consumer
  interoperability, and codec-memory enforcement.
- Added bounded ISO Rock Ridge/SUSP continuation-area reads and writes,
  including multi-sector CE ranges, split NM/SL fields, cycle/range checks,
  and metadata/in-flight/nesting limits.
- Added streaming WinZip AES-256 AE-2 wrapped Deflate64 reads with password
  verification, authentication, exact extent/size checks, truncation failures,
  and decoded-output limits.
- Added streaming 7z PPMd7/variant-H reads through `ppmd-rust`, with validated
  model properties, pre-allocation codec-memory limits, exact no-end-marker
  output bounding, independent `sevenz-rust2` interoperability, corruption
  failures, and a committed fuzz seed.
- Added bounded streaming 7z BCJ2 reads over four independently positioned
  pack extents, with aggregate graph-memory limits, `compcol` producer and
  `sevenz-rust2` consumer interoperability, short-read coverage, corruption
  failures, and a committed fuzz seed.
- Split ecosystem-specific validation into `libarchive_oxide-package`, with
  separate structure, integrity, signature-validity, and offline issuer-trust
  verdicts. Added bounded Alpine APK v2 concatenated-gzip/tar inspection and
  distinct `alpine-apk` / `android-apk` profile IDs without treating signature
  presence as cryptographic success.
- Added offline Alpine APK v2 RSA/SHA-1, RSA/SHA-256, and RSA/SHA-512
  verification over the exact compressed control member plus compressed-data
  `.PKGINFO datahash` checks. Public-key validation, 64 KiB CLI key-file
  bounds, verification-key/trust-pin separation, an official `apk-tools`
  interop fixture, wrong-key/member-tamper failures, and capture/resource-limit
  tests are gated.
- Added streaming JAR SHA-256/384/512 manifest-digest verification and Python
  Wheel `RECORD` hash/size verification through RustCrypto SHA-2, with bounded
  metadata retention and malformed-record and tampering failures. JAR and
  Android APK v1 `.SF` whole-manifest, main-attributes, and exact individual
  section digests plus every CMS signer are verified offline. APK v1 enforces
  uniform per-entry signer coverage; OpenJDK and official AOSP multiple-signer
  fixtures, malformed metadata, folding/line-ending, wrong-signature, trust,
  and resource-limit failures are gated. The CLI emits verified
  signer-certificate SHA-256 fingerprints and accepts only explicit offline
  trust pins.
- Added bounded offline Android APK Signature Scheme v2/v3 verification for
  RSA-PSS, RSA-PKCS#1, and P-256/P-384 ECDSA-with-SHA-256 signed-data, plus
  constant-memory 1 MiB chunked SHA-256/SHA-512 content digests with the
  required EOCD offset rewrite. Official AOSP `apksig` RSA/ECDSA fixtures,
  tampering, malformed size/algorithm lists, trust separation, and resource
  limits are gated. Coexisting v1/v2/v3 schemes are all evaluated so one valid
  scheme cannot mask another scheme's failure; unsupported DSA,
  ECDSA-with-SHA-512/P-521, out-of-backend RSA sizes, and unknown lineage
  algorithms fail explicitly.
- Added bounded APK v3 proof-of-rotation and v3.1 targeted signer verification.
  Every lineage certificate, predecessor signature, declared algorithm, flag,
  active-signer transition, SDK range, release/development boundary, and
  rotation-min-SDK stripping declaration is checked. Standard and fs-verity
  content digests can coexist; the 4 KiB salted fs-verity tree is streamed
  under shared resource limits. Official AOSP positive, tampered, wrong-key,
  stripped, malformed, and resource-limit fixtures are gated, and versioned
  CLI JSON exposes rotation evidence without granting trust.
- Added explicit, offline Android APK Signature Scheme v4/v4.1 `.idsig`
  verification. The bounded parser verifies every signing-info signature,
  exact certificate/SPKI identity, v2/v3 and v3.1 digest binding, and the
  SHA-256 fs-verity-compatible Merkle root/tree. Missing optional sidecars stay
  `not-evaluated`; integrity, signature validity, and caller-pinned trust remain
  separate. `oxarchive package validate --type android-apk --idsig-file PATH`
  never guesses a sibling path and emits a nested versioned JSON result.
  Official CTS/`apksig` v4.0/v4.1 fixtures plus digest mismatch, tamper,
  wrong-APK, unknown-algorithm, I/O, and resource-limit failures are gated.
- Added bounded MSIX/APPX `AppxBlockMap.xml` integrity verification with strict
  XML allocation/nesting/entry limits, exact non-footprint file coverage,
  duplicate/traversal rejection, declared size/LFH/compressed-block checks, and
  streamed SHA-256 over 64-KiB uncompressed blocks. Microsoft MSIX SDK
  interoperability, tamper/resource failures, CLI JSON, and fuzz corpus
  coverage are gated; encrypted/delta 2015/2017 vocabularies are typed
  unsupported, and `AppxSignature.p7x` remains explicitly unevaluated.
- Consolidated the command-line surface into the single `oxarchive` binary,
  retired the partial-compatibility `oxtar`, `oxcpio`, `oxcat`, and `oxunzip`
  targets, and added shell-completion and roff-manual generation.
- Moved provider, registry, range-source, and caller-driven pipeline APIs to the
  `advanced` namespace and removed their duplicate crate-root paths.
- Added ZIP Deflate64 (method 9) read support on portable and native profiles
  through the pure-Rust `deflate64` decoder, with streaming CRC/size/truncation
  and resource-limit enforcement; Deflate64 write remains an explicit won't-do.
- Added the read-only UDF Phase 1 seek provider for 2048-byte UDF
  1.02/1.50/2.01 optical images, including anchor/Main/Reserve recovery,
  continued/prevailing volume descriptors, validated descriptor ranges,
  FE/EFE files, directories, Unicode, allocation extents, sparse data,
  symlinks, hardlinks, POSIX-style metadata, bounded raw inline extended
  attributes, all archive limits, and sync/async/range/engine routes.
- Added bounded continuation and prevailing-descriptor selection for UDF File
  Set Descriptor sequences, plus UDF 2.01 System Stream Directory and named
  stream reads. Streams are emitted beneath the collision-checked,
  percent-encoded `.libarchive-oxide-udf-streams/` namespace with typed
  `udf-stream` owner/kind/metadata extensions and inherited main-file identity
  metadata. Default file-set-zero selection, parent-first/versioned FIDs,
  long-ad and stream Unique IDs, role-correct Stream/metadata flags, EFE Object
  Size, descriptor integrity, partition bounds, graph cycles, and archive
  resource limits fail closed.
- Added bounded UDF 2.50/2.60 Metadata Partition translation/mirror recovery,
  UDF 1.50/2.00+ Virtual Partition/VAT translation, and UDF 1.50+ Sparable
  Partition reads. Sparable maps validate redundant table generations and
  packet ranges, recover from corrupt copies, compose beneath Metadata
  Partitions, and include deterministic failure/limit coverage plus independent
  `mkudffs` 2.3 interoperability evidence. UDF creation remains absent.
- Added `oxarchive create` for tar/cpio/ar/zip plus portable/native outer
  filters through shared `ArchiveEngine`/`CreateOptions`, atomic no-replace
  file publication, bounded `ReaderEvent` inspection, schema-versioned JSON
  Lines records, and an explicit unified CLI exit/stdout/stderr contract.
- Added compile-time `FilesystemAdapter` application, explicit platform
  capabilities, typed applied/unsupported/refused/partial/OS-error findings,
  and a Linux `cap-std` reference adapter for mode/time, numeric ownership,
  xattrs, POSIX ACLs, sparse files, links, special files, and atomic commit.
- Bound built-in extraction preparation and commit to stable parent directory
  capabilities, with a deterministic ancestor rename/symlink race regression,
  so post-preflight path replacement cannot redirect materialization.
- Added statically composed `FormatProvider` and `CodecProvider` chains, typed
  capability queries, provider-aware
  `Pipeline`/reader/engine/create paths, and bounded downstream conformance tests.
- Added additive `portable-codecs` (default) and `native-codecs` profiles for
  gzip, bzip2, zstd, xz/LZMA2, and LZ4, with runtime `BackendPreference`,
  shared conformance/fuzz gates, dependency-graph policy, and benchmark/RSS
  evidence.
- Added bzip2 outer-filter detection, streaming read/write, async/Tokio
  adapters, caller-driven pipeline support, and `oxarchive create --filter
  bzip2`.
- Migrated zstd sync, caller-driven Pipeline, futures-io, and Tokio paths to
  the Pure-Rust `ruzstd` backend with a native-dependency CI gate.
- Migrated xz/LZMA2 sync, caller-driven Pipeline, futures-io, and Tokio paths
  to a bounded Pure-Rust `lzma-rust2` codec with allocation-before-use limits,
  deterministic writes, and a native-dependency CI gate.
- Migrated LZ4 frame sync, caller-driven Pipeline, futures-io, and Tokio paths
  to the Pure-Rust `lz4_flex` backend with bounded framing and a
  native-dependency CI gate.

### Changed

- Removed the duplicate public `ExtractionPolicy`, streaming `Extractor`, and
  `TokioExtractor` paths. The root `Policy` and
  `ArchiveEngine::prepare` → `ArchiveSession::plan` → `apply` are now the only
  filesystem-extraction configuration and execution path, so every adapter
  consumes the same whole-archive destination preflight.

### Fixed

- Made synchronous, asynchronous, Tokio, range-backed, and seek-reader
  ownership recovery fallible, returning a structured protocol error after a
  failed filter/7z graph transition instead of relying on `expect` or
  `unreachable!`; XZ worker channel mismatches are likewise typed errors.
- Made malformed zstd decode errors terminal so mutated frames return a typed
  error instead of reusing decoder state and aborting under libFuzzer.
- Fixed incremental gzip header accounting so body bytes arriving with the
  final header fragment are not retained or charged against the metadata
  budget; a header that actually exceeds the budget still fails before decode.

### Changed

- Replaced the v0.1 slice, sink, and buffering APIs with bounded
  `ArchiveDecoder`, `ArchiveEncoder`, `Codec`, and `Pipeline` state machines.
- Added opaque sequential/seek, futures-io, and Tokio adapters, explicit
  spooling, consuming `finish`, and archive-level metadata setters.
- Expanded typed metadata and lossless raw-extension preservation across tar,
  cpio, ar, ZIP, 7z, and ISO 9660.
- Added finite resource limits, strict trailing-data validation, secure
  capability-based extraction, atomic commit, and zeroizing AES secrets.
- Added all cpio header dialects and hardlink normalization, streaming ZIP
  descriptors, solid 7z processing, Joliet/Rock Ridge, PAX/GNU sparse, ZIP64,
  and WinZip AES.
- Moved the workspace to Rust 2024 and a uniform Rust 1.88 MSRV. Core remains
  dependency-free `no_std + alloc`; portable codecs remain `no_std + alloc`.
- v0.2 intentionally removes v0.1 source compatibility and provides no legacy
  feature or compatibility shim.
