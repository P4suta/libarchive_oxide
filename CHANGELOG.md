# Changelog

Notable changes are generated by [release-plz](https://release-plz.dev).

## [Unreleased]

### Added

- Added bounded Safe Rust support for all five standard RAR3 VM filters:
  Delta, E8, E8/E9, RGB, and Audio.
  A new dependency-free `no_std + alloc` BSD-2-Clause primitive crate validates descriptor bounds, XOR checksums, and length/CRC32 program fingerprints before closed-enum dispatch; it never interprets arbitrary VM bytecode.
  Standard program state continues across sequential solid members, pending invocations and scratch are finite, and a BSD libarchive corpus is verified byte-for-byte under one-byte delivery.

- Added bounded Safe Rust RAR3 PPMd-H/PPMd-II decoding, including the RAR carryless range coder, escape matches, mandatory end markers, in-band block transitions, and statistical-model/output-window continuation across solid members.
  The dependency-free `no_std + alloc` implementation lives in the new `libarchive_oxide-ppmd` primitive crate, uses integer heap offsets rather than pointers or trait objects, and is covered by a CC0 two-member WinRAR corpus plus truncation, corruption, and codec-memory limit tests.

- Added bounded sequential RAR3 solid continuation without dynamic dispatch.
  Completed concrete decoders retain only dictionary, Huffman, and LZ distance state while member input/output, extents, CRC32, and limits reset.
  A real nine-member RAR4 LZ corpus passes under one-byte delivery.
  The later standard RAR3 VM-filter slice retains its program table through the same solid state.

- Moved the legacy RAR3 LZ77/Huffman decoder source into the dedicated RAR crate with recorded MIT source hashes, then removed that crate's entire `compcol` dependency.
  RAR3 and RAR5 now share a minimal crate-private concrete decoder protocol and exact output limiter; the architecture gate requires both owned trees and rejects any generic codec-collection dependency or boxed algorithm dispatch in the RAR boundary.

- Removed duplicate facade single-feature builds from the automatic feature matrix.
  Workspace siblings still compile with every individual feature, the facade's selected depth-2 powerset still covers interaction cells, and the six facade singles outside that powerset have an explicit 1.5-second supplement.
  Warm constituent time fell from 35.6 to 32.3 seconds on the same Windows workspace, while `ci-efficiency` now enforces the non-overlapping coverage split.

- Replaced the remaining public README `Box<dyn Error>` examples with the facade's concrete `Error` or explicit example-local handling.
  The architecture gate now checks public README snippets as well as project-owned Rust, so copied examples no longer teach boxed error dispatch.

- Reduced repeated package-consumer smoke from a fresh duplicate dependency build to the shared workspace Cargo target, disabled incremental artifacts for that isolated check, and removed its unpacked workspace after success.
  Packaged source paths now include a SHA-256 digest of every `.crate` archive:
  unchanged sources safely reuse the shared target, while any changed local package receives a fresh Cargo identity and cannot pick up stale API metadata.
  On the same Windows workspace the corrected path measured 82.1 seconds after package changes and 26.0 seconds warm, versus the former 213.8-second fresh build, while preserving portable/native, runtime, compile-fail, and additive-profile checks.

- Split the bounded read-only RAR3/RAR5 payload implementation into the dedicated Safe Rust, `no_std + alloc` `libarchive_oxide-rar` crate.
  Format framing remains in core and the flagship still joins both sides through the static associated-type provider; architecture, bare-metal, WASI, MSRV,
  packaging, and release gates now enforce the separate dependency boundary.

- Added bounded non-solid RAR 3.x/4.x compressed-file continuation across caller-owned `VolumeSet` sources.
  The physical parser verifies intermediate packed CRC32 values, the logical assembler verifies the final decoded CRC32,
  and the whole-payload codec budget includes its retained packed input.

- Eliminated the remaining archive-algorithm trait objects.
  RAR3/RAR5 container decoders are generic over an associated payload-decoder type and the flagship selects concrete Safe Rust codecs through a closed enum.
  RPM legacy signature verification now uses a closed constant-memory hasher enum for MD5, SHA-1, RIPEMD-160, SHA-2, and SHA-3 and reproduces OpenPGP V2/3/4/6 signature framing without the upstream boxed-digest API.
  All nine digests are differential-tested and an official signed RPM verifies end to end.
  Examples and repository tooling also use concrete errors/generic closures,
  leaving project-owned Rust with zero boxed trait-object syntax.

- Removed the pre-1.0 boxed sequential provider `Registry` and made associated-type `FormatProvider` / `CodecProvider` chains the sole public algorithm extension model.
  `ProviderSet` now lives directly under `advanced`; pipeline, reader, engine/session, writer, package-consumer smoke,
  and automatic conformance tests all use the same closed-enum state.
  ADR-0034 records the decision and the architecture check now rejects boxed trait objects in project-owned Rust.

- Replaced the multi-volume format registry's boxed provider and decoder dispatch with associated decoder types.
  `VolumeArchiveReader` uses a closed built-in enum for CAB, ZIP, RAR, and 7z and offers a generic `with_provider` constructor for downstream formats.
  Focused external-provider,
  missing-volume, built-in detection, and CAB continuation tests cover the allocation-free dispatch boundary.
  This is a pre-1.0 breaking API cleanup;
  storage source and resolver trait objects remain deliberately separate from archive algorithm dispatch.

- Added bounded read-only LHA `-lh2-` decoding through the isolated codec crate.
  The existing seek-native container state machine retains headers,
  declared extents, metadata, skip behavior, and CRC16, while the codec preflights whole packed/output buffering, its 8 KiB input window and dictionary, adaptive trees, and conservative allocation growth.
  Exact sizes,
  truncation, CRC failure, limits, skip, RAR shared-adapter regression, fuzz replay, and a provenance-recorded compcol 0.6.8 vector cover the path.
  The vector is explicitly same-codec evidence rather than independent producer interoperability evidence; LHA writing remains unsupported.
  The stable LHA corpus-mutant replay is split into four deterministic shards so the test harness can exercise the same mutants concurrently in normal CI.

- Added bounded read-only LHA `-lh3-` block decoding with canonical literal/length and distance trees, 8 KiB history, prehistory fill, extended matches, exact declared-size enforcement, and CRC16 verification.
  Packed input, decoded output, the fixed input window, history, and tree workspace are preflighted before allocation.
  The flagship reuses its container reader through a private LH2/LH3 enum rather than `Box<dyn Codec>`, keeping dynamic dispatch and an extra codec allocation out of this built-in hot path.
  A provenance-recorded first-party vector covers canonical trees, matches,
  limits, truncation, CRC failure, skip, and stable fuzz replay; it is not represented as independent producer evidence.
  LHA writing remains absent.

- Added a generic `PayloadCodecProvider` boundary between format containers and independently replaceable payload codecs.
  The flagship's feature-gated built-in provider uses the attributed MIT-licensed, Safe Rust decoders owned by `libarchive_oxide-rar` for legacy RAR methods `0x31`–`0x35` and RAR5 generation-0 methods 1–5.
  RAR3 whole-payload buffers and each self-described RAR5 block,
  output, dictionary, and codec workspace are preflighted before allocation;
  RAR5 total packed size is only an integrity counter, and decoded sizes plus CRC32/BLAKE2sp are verified.
- Stream one non-solid generation-0 RAR5 codec state across split volumes,
  validating intermediate packed CRCs, final plaintext CRC32/BLAKE2sp, exact decoded size, missing volumes, and logical archive budgets.
- Continue completed generation-0 RAR5 decoders across sequential solid members through the generic provider boundary without type erasure.
  Each member revalidates exact packed/output limits and dictionary identity; a BSD-licensed libarchive v3.8.8 four-file solid corpus verifies cross-member references.
- Continue that same concrete RAR5 decoder through caller-owned physical volume readers, including a solid member whose packed stream is itself split across volumes.
  The volume layer now owns all compressed payload state, verifies physical and logical checksums, rejects missing state, changed dictionaries,
  and inconsistent solid flags, and never boxes algorithm dispatch.
- Decode sequential generation-0 compressed RAR5 comment, quick-open, recovery,
  ACL, and alternate-stream services through an independent concrete provider decoder.
  A new protocol progress event keeps internally retained or discarded plaintext out of entry-data events while preserving bounded driver work,
  exact packed/unpacked sizes, CRC32/BLAKE2sp, metadata, and decoded/codec budgets without disturbing solid-file continuation state.
- Honor RAR5's common skip-if-unknown flag: known headers accept the advisory flag, while unknown CRC-checked headers discard only their declared data extent and resume parsing; mandatory unknown and truncated data fail closed.
  Real compressed-byte fixtures, one-byte delivery, truncation, limit,
  feature-off, capability, and fuzz replay tests cover the boundary.
  PPMd,
  RarVM and rare RAR5 filters, generation 1, decryption, and every RAR writer remain unavailable and explicitly reported.

- Moved the RAR5 LZ77/Huffman decoder into the dedicated Safe Rust RAR codec crate with pinned MIT source hashes, removed the `compcol/rar5` feature, and added Delta and ARM filters.
  The owned decoder now caps pending descriptors,
  rejects filters that reach backward into emitted output, consumes at most one self-described block per call, and charges Delta scratch to `codec_memory`.

- Split the dependency-free `libarchive_oxide-protocol` crate below archive formats and portable codecs.
  It owns the shared Safe Rust `no_std + alloc` byte-codec protocol, finite limits, and structured errors;
  `libarchive_oxide-core` preserves the old paths as identical re-exports while `libarchive_oxide-codecs` no longer depends on format core.
  Package verification and the CLI now consume only their public flagship/package facades instead of bypassing them for core or codec types.
  A deterministic architecture gate, package consumer type-identity smoke, bare-metal/WASI,
  MSRV, and workspace feature checks keep the dependency direction fixed.

- Kept the declared Rust 1.88 MSRV honest for the full LHA and 7z evidence surfaces.
  The published `delharc` 0.8.0 source is now carried as the publishable `libarchive_oxide-delharc` helper with post-1.88 syntax and APIs backported to checked Safe Rust, while retaining LHx and PMArc decoding.
  The dev-only `sevenz-rust2` 0.21.3 source is pinned to its Rust-1.88-compatible `nt-time` API.
  Provenance, license packaging, external package resolution,
  all-feature MSRV checks, LHA fuzz replay, and 7z differential tests cover both maintained sources.

- Legacy RAR 3.x/4.x main-header encryption now exposes raw main flags, the optional encryption version, and a `rar-legacy/header-encryption` archive marker from one-byte input.
  The next event returns typed `Unsupported` before encrypted header bytes can be parsed as plaintext.
  Synthetic valid-envelope fuzzing varies version presence and value on every replay; header decryption remains unavailable.

- Legacy RAR 3.x/4.x file-encryption flags now expose `EntryMetadata::is_encrypted()` from one-byte input for known `0x30`-`0x35` methods, preserve the raw method and optional fields, validate fixed 8-byte salts, and allow ciphertext/plaintext size differences.
  Payload access still returns typed `Unsupported` before ciphertext can escape as `Data`; encrypted stored symlink targets remain fail-closed.
  Synthetic valid-envelope fuzzing exercises salted/unsalted and Store/compressed headers on every replay.

- RAR5 header-encryption headers now strictly validate the AES-256 version,
  known flags, KDF-count byte, 16-byte salt, optional 12-byte password check,
  forbidden common fields, placement, truncation, and trailing data.
  Valid headers expose raw `rar5/header-encryption` archive metadata from one-byte input before encrypted-header access returns typed `Unsupported`; ciphertext is never parsed as a plaintext header.
  Synthetic valid-envelope fuzzing covers the same boundary.
  Header decryption remains unavailable.

- RAR5 file-encryption extra records now validate the AES-256 version, known flags, KDF-count byte, 16-byte salt, 16-byte IV, optional 12-byte password check, duplicates, and trailing data.
  Valid records expose `EntryMetadata::is_encrypted()` from one-byte input before payload access returns typed `Unsupported`; ciphertext is never emitted as entry data.
  Synthetic valid-envelope fuzzing covers the same boundary.
  Header and data decryption remain unavailable and are not claimed.

- Added bounded PMArc `-pm1-` and `-pm2-` decoding to the seek-native LHA reader.
  The fixed 16 KiB and 8 KiB histories are rejected against `Limits::codec_memory` before decoder construction, and dependency-side unchecked assertion elision is disabled.
  Lhasa PMArc 1.24/2 fixtures lock paths, methods, decoded lengths, independent CRC32 values, truncation,
  exact/under memory bounds, and stable fuzz replay.

- Added bounded forward-only ZIP PPMd8 reads for plain, traditional ZipCrypto,
  and WinZip AES entries.
  Known local extents and signed or unsigned classic/ZIP64 descriptors stream through a Safe-Rust pull worker that acknowledges only range-decoder-owned input, preserving descriptor and authentication look-ahead without whole-member buffering.
  Parameter words and model memory are validated before allocation; CRC32, sizes,
  authentication, truncation, decoded limits, one-byte sync/futures and buffered sync/Tokio input, independent `zip` output, and valid-envelope fuzz replay cover the new path.

- Added bounded forward-only ZIP LZMA reads for plain, traditional ZipCrypto,
  and WinZip AES-128/192/256 entries.
  Known local extents accept both EOS-marker and declared-size conventions; EOS-terminated streams additionally accept signed or unsigned classic/ZIP64 descriptors.
  The Safe-Rust pull worker acknowledges only range-decoder-owned input, leaving queued descriptor and authentication bytes uncommitted without buffering a whole member.
  CRC32,
  sizes, authentication, truncation, dictionary memory, per-entry, and aggregate decoded limits are enforced across one-byte sync/futures and buffered sync/Tokio input, committed CPython/liblzma evidence, and valid-envelope fuzz replay.
  Descriptor-framed LZMA without an EOS marker remains typed `Unsupported` because it has no independently knowable codec boundary.

- Added bounded forward-only ZIP Deflate64 reads with signed or unsigned classic/ZIP64 data descriptors for plain, traditional ZipCrypto, and WinZip AES-128/192/256 entries.
  A minimally patched vendored MIT `deflate64` 0.1.12 exposes its existing exact checkpoint position, so Huffman look-ahead remains uncommitted in the pipeline instead of consuming descriptor bytes.
  Official 7-Zip 64 KiB-window data, one-byte and buffered sync/futures/Tokio input, authentication and descriptor tamper, truncation, bomb limits, and valid-envelope fuzz replay cover the shared state machine without entry-sized buffering.

- Added ZIP writer support for typed low-byte non-directory DOS file flags in the central directory.
  Seek reads now round-trip those flags alongside Unix mode bits, while the structural directory marker and wider masks fail closed.
- Added lossless typed 7z Windows file-attribute reads and writes alongside the existing Unix mode extension.
  Native Windows attribute words retain all non-directory bits on read; writing accepts the non-conflicting low-bit subset and rejects the structural directory and Unix-marker bits.
- Promoted RAR5 Windows attributes and legacy RAR DOS/OS2/Windows attributes to typed `file_flags` while preserving their raw extensions.
  The structural directory marker remains an entry-kind signal rather than a restorable flag,
  and sequential RAR5 extraction now drives the Windows adapter end to end.
- Projected non-directory ZIP central-directory DOS attributes into typed `file_flags` on seek reads.
  The Windows capability-rooted adapter now restores regular-file `HIDDEN`, `SYSTEM`, and `ARCHIVE` at staged creation plus a lone `READONLY` after atomic publication; unsafe combinations and unsupported bits remain payload-preserving typed `Partial` findings.
- Added forward-only traditional ZipCrypto reads for Store, Deflate, BZip2,
  Zstandard, XZ, and read-only Deflate64 through the common sync, futures, and Tokio `OpenOptions` password provider.
  Known local sizes and signed classic/ZIP64 descriptors stream without an archive-sized buffer; ordered candidates, the 12-byte encryption header,
  committed ciphertext counts, CRC32, decoded-size and resource limits produce typed password, tamper, truncation, and bomb failures.
  Deflate64 additionally accepts unsigned classic/ZIP64 descriptors through exact inflater checkpoints.
- Added forward-only WinZip AES-128/192/256 AE-2 reads for Store, Deflate,
  BZip2, Zstandard, and XZ with known local sizes or signed classic/ZIP64 data descriptors.
  Ordered password candidates, bounded one-byte sync/futures/Tokio input, typed authentication/truncation/limit failures, and HMAC-confirmed XZ stream padding share the same sequential reader.
  Deflate64 now composes with the same authenticated path for known sizes or signed/unsigned classic/ZIP64 data descriptors.
- Extended the forward-only ZIP reader with feature-gated XZ method 95 for known local sizes and signed classic/ZIP64 descriptors.
  A bounded structural scanner keeps descriptor bytes outside the decoder and shares the XZ allocation-header checks.
  The common pipeline state preserves portable/native decoder selection and enforces CRC32, size, extent, truncation, codec-memory, entry, and aggregate limits;
  unsigned XZ descriptors remain typed `Unsupported` on this path.
- Extended the forward-only ZIP reader with Zstandard method 93 for known local sizes and signed or unsigned classic/ZIP64 descriptors.
  A fixed-size frame tracker keeps descriptor bytes outside the portable/native decoder,
  while CRC32, size, truncation, trailing-data, codec-memory, entry, and aggregate limits remain enforced.
- Extended the forward-only ZIP reader with feature-gated Deflate64 for entries whose local headers declare their compressed and decoded sizes.
  The pure-Rust inflater preserves the exact compressed extent despite bit look-ahead, preflights its fixed workspace against `codec_memory`, and enforces CRC32, size, truncation, trailing-data, entry, and aggregate limits.
  Signed/unsigned classic/ZIP64 data descriptors use exact checkpoint accounting; Deflate64 writing remains unavailable.
- Added a bounded forward-only ZIP/ZIP64 reader to the common sync,
  futures-io, and Tokio APIs.
  Store, Deflate, and feature-gated BZip2 stream from local headers with known sizes or classic/ZIP64 data descriptors;
  self-terminating compressed methods accept signed and unsigned descriptors,
  while Store requires the optional signature to avoid an ambiguous payload boundary.
  CRC32, decoded/entry/metadata/path/in-flight limits, structural trailer parsing, truncation, and local/central entry-count agreement are enforced without retaining entry payloads.
- Added standard split ZIP/ZIP64 reads through the common bounded `VolumeSet` path.
  Central-directory and local-header offsets are translated from their declared disks instead of treating segments as a plain byte split;
  Store and the existing compressed/encrypted ZIP decoders stream across physical boundaries.
  Explicit terminal `.zip` discovery derives exactly the EOCD-declared `.z01`, `.z02`, ...
  sources, preserves typed missing/limit errors, and is exposed by `oxarchive --discover-volumes`.
- Generalized explicit path-only adjacent-volume discovery from numeric split 7z inputs to modern `.part1.rar` RAR sets and legacy RAR 3.x/4.x `.rar`/`.r00` sets.
  Derived names remain in the primary directory,
  preserve width and case, and run under `SourceLimits`.
  Volume sessions now traverse once before fixing their digest so every required encoded source,
  including lazily reached RAR continuations, is part of the plan identity.
  `oxarchive --discover-volumes` exposes the same 7z/RAR boundary.
- Added bounded RAR 3.x/4.x physical-volume sequencing for complete and split Store entries.
  The common `VolumeArchiveReader` follows verified ENDARC continuation flags through a caller-owned `VolumeSet`, rejects misplaced first-volume flags, preserves typed missing-volume errors, and carries entry/decoded budgets across the logical archive.
  Split Store file parts form one logical entry after non-final packed CRC32 (when present), final logical CRC32, continuation metadata, declared-size, and archive-wide budget validation.
- Added bounded RAR5 physical-volume sequencing for complete and split Store entries.
  `VolumeArchiveReader` follows authenticated end-header continuation declarations through a caller-owned `VolumeSet`, validates explicit volume numbers, preserves one logical event stream, and reports typed missing-volume errors.
  Split Store file parts are exposed as one entry after per-part packed and final logical CRC32/BLAKE2sp, continuation metadata, declared-size, and archive-wide budget validation.
  Split service payloads, compression, and encryption remain explicit unsupported paths.
- Made control-like cpio and mtree paths fail closed.
  Cpio writers and transcoding now reject the exact `TRAILER!!!` end marker before entry output;
  mtree writers continue to octal-escape comment-looking names and now reject absolute or NUL-containing paths that their reader cannot represent.
- Made ar short-name encoding control-safe and independently interoperable.
  Paths that resemble GNU symbol/name-table references or BSD `#1/LEN` controls now use four-byte-padded BSD inline names, readers remove only the specified trailing NUL padding, and transcoding includes the padded name in the ten-digit member-size preflight.
  `/`, `/SYM64`, `/123`, and `#1/7` round-trip through both first-party and `ar@0.9` consumers.
- Made filesystem creation metadata destination-aware.
  The shared streaming and seek builders now project host mtimes to ZIP whole seconds, ISO 10 ms,
  and 7z 100 ns/FILETIME ranges, apply cpio/ar time bounds, and retain numeric owners only where the selected wire format can represent them.
  This keeps strict lossless-or-error writers usable from `oxarchive create` without weakening their direct-entry contracts.
- Made WARC transcoding explicit about synthesized filesystem metadata.
  WARC destinations now require a declared size during projection, normalize the virtual mode to `0644`, and report the source entry path as `EntryPath` because the wire format retains record headers rather than archive paths.
  `oxarchive convert --json` exposes this loss as `entry_path`.
- Made fixed-width destination projection size- and mode-aware.
  Transcoding now rejects cpio/ISO declarations above u32 and ar members above its ten-digit field (including BSD inline-name bytes) before writer dispatch; cpio/ar also report missing required sizes.
  Tar/cpio/ar/ZIP preserve only the lower 12 permission bits with an explicit mode loss, while direct writers reject higher mode bits before emitting output instead of silently masking them.
- Made Tar device metadata kind- and range-exact.
  Char/Block entries require a referenced device whose major/minor fit the 8-byte GNU base-256 field through `2^56-1`; other kinds reject or explicitly lose such metadata, and unsupported Tar entry kinds now fail during transcoder projection rather than writer dispatch.
- Made cpio/ISO numeric metadata projection wire-aware.
  In-range u32 inode,
  link-count, and device values now transcode losslessly (including cpio→ISO Rock Ridge PX); oversized optional values become explicit losses, while an unrepresentable required ISO character/block device fails before entry output.
- Made global Tar PAX metadata lossless-or-error at the archive boundary.
  Opaque vendor records and last-wins comment multiplicity still round-trip;
  keys that would silently override future entry paths, sizes, owners, times,
  xattrs, ACLs, or sparse maps are rejected or reported by transcoding.
- Made GNU sparse PAX write-back field-exact and fail-closed.
  Coherent raw map or offset/numbytes records and `size`/`realsize` spelling now survive repeated Tar re-encoding without canonical replacement; global, contradictory,
  malformed, untyped, or unsupported GNU sparse properties fail before header output.
- Made ZIP typed comments distinguishability-safe.
  Empty typed archive or file comments now fail before entry output because ZIP encodes them identically to absent comments; archive transcoding reports both cases as explicit metadata loss.
  Nonempty comments and applicable Unicode-comment extras are unchanged.
- Made 7z raw archive-property write-back lossless-or-error.
  The writer rejects the archive end marker and container-owned FilesInfo properties before entry output instead of accepting and skipping them; the transcoder reports those structural raw properties as archive-extension loss while unknown properties continue to round-trip.
- Made direct ISO entry writes lossless-or-error for all typed metadata.
  The writer rejects hardlinks, owner names, oversized PX/PN numeric fields, lossy modes, filesystem device/flags/checksum/comment fields, and declared sizes above the directory-record u32 range before entry output; transcoding now reports ISO entry comments and unsupported hardlink kinds as metadata loss.
- Made sequential ZIP entry metadata lossless-or-error.
  The writer now rejects unsupported kinds/owner names/partial or oversized IDs/times/filesystem fields before output, owns bounded unencrypted symlink-target payloads, and reports symlink size projection during transcoding.
  Encrypted symlinks are rejected until password-backed metadata hydration can recover their target.
- Made ZIP structured-extra write-back fail closed and field-exact.
  Raw Extended Timestamp, NTFS, and Info-ZIP Unix values must agree with their typed time/owner projection; malformed bodies are rejected before output, missing fields alone are synthesized, and coherent NTFS creation times plus 100 ns precision survive repeated seek-reader/writer round trips.
- Made applicable Info-ZIP Unicode path/comment extras agree with the typed path/comment or fail before output; invalid applicable UTF-8 is malformed,
  while stale-CRC extras from a seek-reader round trip remain preserved and inert.
  ZIP directory suffixes are now added before pathname limit and u16 field checks, closing the 65,535-byte plus slash overflow boundary.
- Made ISO and 7z timestamps range-aware and lossless-or-error.
  ISO accepts only year 0–9999 at 10 ms precision; 7z uses checked 100 ns `u64` FILETIME conversion instead of saturating through `i64` and rejects non-mtime fields.
  Their full lower/upper wire ranges round-trip, and transcoding now reports out-of-range values as explicit timestamp losses.
- Made 7z direct entry writes lossless-or-error for typed metadata.
  Unsupported kinds, owner/inode/device/sparse/xattr/ACL/flag/checksum/encryption/comment/raw fields, lossy mode values, non-UTF-8 or NUL names, and invalid directory or symlink sizes now fail before entry output.
  Tar→7z symlinks project to their metadata-owned target size and do not duplicate the source payload.
- Made Tar PAX metadata re-encoding stable and fail-closed.
  Entry comments now decode into their typed field, existing raw uname/gname/time/xattr/ACL/comment records are not duplicated, and conflicts with typed path/link/owner/time/ size/xattr/ACL/comment metadata are rejected before header output.
- Extended sequential writer fail-closed validation beyond extensions.
  Tar now rejects device/inode/link-count/flags/checksum/encryption fields it cannot encode; cpio rejects owner names, non-mtime timestamps, sparse/xattr/ACL and other unsupported fields while retaining dialect-correct CRC sums.
  Cpio and ar also reject negative or fractional modification times instead of rounding them, and ar bounds every fixed-width numeric header field before output.
- Closed direct-writer extension loss in Tar, cpio, and ar.
  Tar now rejects non-PAX entry extensions, while cpio and ar reject all entry extensions they cannot encode, consistently returning `Unsupported` before header output.
- Made ISO and ZIP raw entry extensions lossless-or-error.
  ISO now accepts only canonical, fully framed unknown SUSP fields and rejects typed/reserved or foreign fields; ZIP accepts two-byte non-structural extra IDs and rejects malformed IDs plus container-owned ZIP64/AES extras.
  Transcoding drops these values with an `EntryExtensions` loss instead of forwarding them to a writer that would ignore or rewrite them.
- Rejected empty ISO system/application identifiers and values ending in the padding bytes space or NUL.
  The reader necessarily trims those suffixes, so direct writes now fail closed and transcoding reports `ArchiveExtensions` loss instead of claiming an inexact round trip.
- Made ISO volume names lossless-or-error at the public metadata boundary.
  Names that would be uppercased, replaced, or truncated in the primary volume descriptor now return typed `Unsupported` from the writer and become an `ArchiveVolumeName` loss in transcoding; exact names through the 32-byte boundary still round-trip.
- Fixed archive-metadata replacement in ISO and 7z seek writers so the bounded metadata budget contains the current property set rather than every prior call to `set_archive_metadata`.
  ISO primary descriptors now also retain the application identifier: reserved-field initialization previously erased it after encoding.
- Closed silent archive-metadata loss in the sequential Tar and ZIP writers.
  Tar now rejects volume names, non-PAX extensions, and conflicting typed/PAX comments; ZIP accepts archive comments but rejects volume names and extensions.
  Both return typed `Unsupported` before producing entry bytes.
- Made ISO 9660 archive-volume metadata lossless-or-error.
  The seek writer now rejects unknown or duplicate `iso9660-volume` keys and overlong system or application identifiers instead of accepting and silently ignoring or truncating them.
  Archive transcoding preserves the first representable value and reports all rejected values as `ArchiveExtensions` metadata loss.
- Stabilized 7z AES encrypted-header password trials across every decrypted byte pattern.
  Decoder-originated I/O-shaped failures are candidate-local and exhaust to typed `Integrity`, while an internal source marker preserves real seek/read failures as `Io`.
  A fixed independent-producer salt/IV reproduces the former flaky path, and an injected source failure proves it is not hidden.
- Applied ISO 9660 descriptor geometry checks equally to primary and Joliet trees.
  Both-endian logical block sizes must agree and the supported size is 2,048 bytes; each descriptor's embedded root record must have its fixed length, root identifier, directory-only flags, and zero interleave widths.
  Invalid supplementary geometry can no longer be interpreted using primary defaults.
- Validated ISO 9660 volume-set sizes and volume sequence numbers in primary,
  Joliet, embedded-root, and every directory record.
  Entries on the current member of a multi-volume set remain readable; a record that names another volume now returns typed `Unsupported` before its LBA can be mistaken for a local offset.
  Zero, out-of-set, inconsistent both-endian, and mismatched root identifiers are malformed.
- Enforced the ISO 9660 `Volume Space Size` as the reader's logical boundary.
  Primary and Joliet descriptors validate both-endian sizes against the physical source and descriptor-set terminator; root/child directories, extended attributes, SUSP continuations, and regular, multi-extent, or interleaved file spans cannot consume appended trailer bytes.
  Harmless trailing bytes remain accepted when no ISO structure references them.
- Hardened ISO 9660 directory traversal to reject records that cross a 2,048-byte logical-block boundary and nonzero bytes after the first padding marker.
  Padding validation scans at most the remainder of one block before advancing, preserving bounded-memory indexing.
- Added bounded ISO 9660 extended-attribute record reads.
  File, root-directory,
  and child-directory data begin after their declared EA allocation; the reader retains only the fixed 250-byte record plus declared application/escape data rather than every allocated block.
  ECMA owner/group identifiers,
  read/execute permissions, creation/modification times, and a semantic raw record are exposed in entry metadata, with Rock Ridge fields taking precedence.
  Version, both-endian lengths, mandatory permission bits,
  record/protection flags, timestamps, reserved bytes, image ranges, metadata, and in-flight memory are validated before payload delivery.
- Added bounded ISO 9660 interleaved file reads across sync, futures-io,
